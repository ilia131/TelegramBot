# ربات تلگرام فروش اشتراک هیدیفای، نسخهٔ ۱

> این نسخه برای آزمایش گردش کار ساخته شده است. تا زمانی که API نسخهٔ نصب‌شدهٔ هیدیفای بررسی و تحویل خودکار اشتراک در محیط آزمایشی تأیید نشده، از مشتریان وجه واقعی دریافت نکنید. پرداخت مستقیم برای عموم غیرفعال است. حالت آزمایشی مدیران فقط برای رسید ساختگی است.

ربات منوی فارسی، انتخاب پلن، سفارش، بررسی دستی رسید و انتخاب نام کانفیگ دارد. هفت پلن ۳۰روزه در `app/plans.py` تعریف شده‌اند. مبلغ و مدت هر سفارش مستقل از تغییرات بعدی پلن ذخیره می‌شود. SQLite در یک volume مجزا نگه‌داری می‌شود و پردازش اعلان‌ها و سفارش‌های تأییدشده بعد از راه‌اندازی مجدد ادامه پیدا می‌کند.

## پیش‌نیازها

- اوبونتو ۲۴٫۰۴ با Docker Engine و افزونهٔ Docker Compose v2. برای اجرای محلی بدون Docker از Python 3.12 استفاده کنید.
- اتصال خروجی HTTPS به Telegram Bot API و دسترسی به Docker Hub و PyPI برای ساخت تصویر.
- فضای کافی برای تصویر Docker، پایگاه داده و پشتیبان. سرویس به ۱۹۲ مگابایت حافظه و نیم هسته محدود شده است.

Docker را با [راهنمای نصب از مخزن رسمی در اوبونتو](https://docs.docker.com/engine/install/ubuntu/) نصب کنید. پس از افزودن مخزن و کلید رسمی، این بسته‌ها را نصب و سرویس را فعال کنید.

```bash
sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker compose version
```

اگر حساب شما به Docker دسترسی ندارد، دستورهای Docker این راهنما را با `sudo` اجرا کنید. Compose پروژهٔ مستقل `hiddify-sales-bot-v1` را می‌سازد. Long Polling به پورت ورودی یا دامنهٔ جدید نیاز ندارد. شبکه و volume پروژه مستقل‌اند و فایل‌ها و کانتینرهای هیدیفای در این فرایند دست‌نخورده می‌مانند.

## ساخت ربات و تنظیم مدیران

۱. در تلگرام به حساب رسمی `@BotFather` پیام بدهید و `/newbot` را اجرا کنید. نام و نام کاربری انتخاب کنید و توکن را در محل امن نگه دارید.

۲. در پوشهٔ پروژه، فایل تنظیمات را بسازید.

```bash
cp .env.example .env
chmod 600 .env
```

۳. توکن را در `BOT_TOKEN` بنویسید. شناسه‌های عددی را در `ADMIN_IDS` با ویرگول جدا کنید. اگر هنوز شناسهٔ خود را نمی‌دانید، موقتاً `ADMIN_IDS=1` و `DEMO_PAYMENTS=false` بگذارید، ربات را راه‌اندازی کنید و در گفت‌وگوی خصوصی با ربات `/myid` را بفرستید. مقدار موقت را با شناسهٔ نمایش‌داده‌شده جایگزین و سرویس را دوباره ایجاد کنید. هر مدیر باید پیش از آزمایش در گفت‌وگوی خصوصی با ربات `/start` بزند تا اعلان‌ها به او برسند.

| متغیر | کاربرد |
| --- | --- |
| `BOT_TOKEN` | توکن BotFather |
| `ADMIN_IDS` | فهرست شناسه‌های عددی تلگرام مدیران |
| `CARD_NUMBER` و `CARD_HOLDER` | مشخصات کارت برای نمایش در سناریوی آزمایشی. در حالت آزمایشی هر دو مقدار را در فایل محلی تنظیم کنید. |
| `DATABASE_PATH` | داخل کانتینر، مقدار پیش‌فرض `/app/data/bot.db` |
| `SUPPORT_USERNAME` | نام کاربری اختیاری پشتیبان تلگرام |
| `DEMO_PAYMENTS` | برای آزمایش مدیران `true` و در استفادهٔ عادی `false` |
| `HIDDIFY_BASE_URL` و `HIDDIFY_API_TOKEN` | جای رزروشده برای آدرس و اعتبارنامهٔ نسخهٔ تأییدشدهٔ API |

یک روند polling برای هر توکن اجرا کنید. آزمون و بهره‌برداری را با ربات‌های جداگانه انجام دهید.

## اجرا و نگه‌داری

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f
docker compose restart bot
docker compose stop bot
```

پس از تغییر `.env`، دستور `docker compose up -d --force-recreate bot` را اجرا کنید تا متغیرهای جدید وارد کانتینر شوند. بررسی سلامت کانتینر دسترسی خواندن به SQLite را کنترل می‌کند. اتصال تلگرام را می‌توان با ارسال `/start` جداگانه بررسی کرد.

برای آزمایش، `DEMO_PAYMENTS=true` را تنظیم کنید و با حساب مدیر یک پلن انتخاب کنید. پرداخت مستقیم و سپس دکمهٔ «پرداخت کردم، ارسال رسید» را بزنید و یک تصویر ساختگی حداکثر ۱۰ مگابایت را به‌شکل عکس بفرستید. تصویر در تلگرام می‌ماند و شناسهٔ فایل در SQLite ثبت می‌شود. اعلان به مدیران ارسال می‌شود و اولین تصمیم معتبر ثبت می‌ماند. پس از تأیید، در پاسخ مستقیم به پیام درخواست نام، نام کانفیگ را وارد کنید. در صورت از دست رفتن پیام، بخش «مدیریت اشتراک خریداری‌شده» امکان درخواست دوبارهٔ آن را فراهم می‌کند.

اعلان‌ها با وضعیت سفارش در یک تراکنش ثبت می‌شوند و خطاهای موقت دوباره امتحان می‌شوند. اگر فرایند بین ارسال در تلگرام و ثبت نتیجه در SQLite متوقف شود، ممکن است یک اعلان دوباره ارسال شود. تصمیم مدیر فقط یک بار ثبت می‌شود.

## پشتیبان‌گیری از SQLite

هنگام اجرای ربات از API پشتیبان‌گیری آنلاین SQLite استفاده کنید تا داده‌های WAL نیز در نسخهٔ سازگار لحاظ شوند. دستور زیر با مسیر پیش‌فرض پایگاه داده کار می‌کند.

```bash
backup_file="bot-backup-$(date +%F-%H%M%S).db"
docker compose exec -T bot python - <<'PYTHON'
import os
import sqlite3
from contextlib import closing

os.umask(0o077)
with closing(sqlite3.connect(os.environ["DATABASE_PATH"])) as source:
    with closing(sqlite3.connect("/tmp/bot-backup.db")) as destination:
        source.backup(destination)
PYTHON
docker compose cp bot:/tmp/bot-backup.db "./$backup_file"
chmod 600 "$backup_file"
docker compose exec -T bot rm -f /tmp/bot-backup.db
```

پشتیبان را در مکانی امن خارج از سرور نگه دارید. برای بازیابی ابتدا ربات را متوقف کنید و پایگاه داده را با نسخهٔ معتبر در volume جایگزین کنید. مالک فایل در کانتینر باید UID و GID هر دو برابر ۱۰۰۰۱ باشد. قبل از جایگزینی، از دادهٔ فعلی هم پشتیبان بگیرید و فایل‌های جانبی `bot.db-wal` و `bot.db-shm` متعلق به پایگاه قبلی را همراه آن کنار بگذارید. گزینهٔ `docker compose down -v` داده‌های volume را حذف می‌کند.

## اتصال به هیدیفای و امکانات غیرفعال

در کد رسمی بالادست [آداپتور سمت مدیریت هیدیفای پنل](https://github.com/hiddify/HiddifyPanel/tree/main/hiddifypanel/panel/commercial/restapi/v2/admin) بررسی شد. نسخهٔ نصب‌شدهٔ سرور و قرارداد عملیاتی آن در دسترس نبود. در این نسخه، `app/integrations/hiddify.py` رابط مورد نیاز را با `NotImplementedError` تعریف می‌کند. تنظیم دو متغیر `HIDDIFY_*` به‌تنهایی اتصال را فعال نمی‌کند.

برای پیاده‌سازی اتصال، نسخهٔ دقیق نصب‌شده را از پنل بگیرید و قرارداد API همان نسخه را در یک پنل آزمایشی بررسی کنید. آدرس پایهٔ HTTPS و اعتبارنامهٔ مدیریت را براساس قرارداد همان نسخه در متغیرهای مربوط تنظیم کنید. سپس ایجاد کاربر، حجم، مدت و زمان شروع اعتبار، نشانی اشتراک برای دامنهٔ اشتراک پنل، مصرف، تمدید و غیرفعال‌سازی را در پیاده‌سازی رابط پوشش دهید. پیش از تحویل، تأیید کنید که تکرار درخواست ایجاد پس از قطع اتصال کاربر دوم ایجاد نمی‌کند. شناسه و وضعیت تأییدشدهٔ پنل را در SQLite ذخیره کنید و تنها بعد از تأیید ایجاد، نشانی واقعی و QR متناظر را ارسال کنید.

ثبت نام کانفیگ با وضعیت «در انتظار فعال‌سازی» پایان می‌یابد. ایجاد اشتراک، تحویل لینک و QR، تازه‌سازی مصرف، تمدید و غیرفعال‌سازی فعلاً فعال نیستند. ساختار کیف پول و تراکنش‌ها وجود دارد و شارژ و پرداخت از کیف پول غیرفعال هستند.

## آزمون محلی

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m compileall -q app tests
python -m unittest discover -s tests -v
docker compose config --quiet
```

آزمون‌ها با پایگاه موقت و درخواست‌های شبیه‌سازی‌شدهٔ تلگرام اجرا می‌شوند و نیازی به توکن یا دسترسی به پنل ندارند.
